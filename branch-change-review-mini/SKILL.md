# Branch Change Review

## 输入

- 目标分支，默认尝试识别仓库主开发分支
- 需求目标
- 实施计划或规格文档

## 工作流程

1. 确定比较基线。
2. 查找需求和计划。
3. 检查提交历史和完整 diff。
4. 按功能而不是按文件解释变更。
5. 将实现与需求逐项对应。
6. 识别偏离目标、遗漏、复杂度和过度设计。
7. 输出整体合理性判断。

若缺少需求或计划，先在代码库中查找；找到候选内容后要求用户确认。
